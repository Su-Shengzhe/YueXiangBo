# 第11—12周详细实施计划：统一模型网关与AI停车助手

日期：2026-11-03；版本：V1.1（加入供应商可替换的统一模型网关）。状态：规划，未表示执行或验收完成。实施主体为一名学生开发者，指导教师参与阶段评审。

## 1. 目标与预算

交付统一大语言模型网关、自然语言找车位、规则问答、本人账单解释，以及多轮补全、知识维护、调用追踪和异常降级。第12周末形成候选版本并冻结新增功能；第13—14周完成正式三轮评测、负载及对照实验。

按项目周次编排，不绑定自然日期。两周预算为AI开发、联调和基础测试40小时，专项测试4小时，风险缓冲4小时；每周22小时实施。新增网关管理、版本化切换及兼容验证须纳入第2天复估，不把44＋4小时视为无条件承诺。已知前期欠项单独登记，不直接记作缓冲消耗。

当前AI仍需正式三类场景实现；已有模型桩或网关探索性代码仅作为可评估复用资产，不能代替产品选型和能力验收。M3正式结算、对账欠项独立跟踪，本阶段补齐必需账单事实，不把全部M3补做工作挤入AI预算。

## 2. 统一大语言模型网关要求

```text
AI业务编排
  → 固定调用入口＋逻辑模型别名 parking-assistant
  → 统一大语言模型网关
  → 当前配置的供应商及其具体模型
```

### 管理与职责

- 提供管理员页面：供应商配置列表、添加与编辑、密钥更新、连通性及能力测试、启停、当前活动配置、发布切换、恢复上一配置和脱敏调用日志。
- 配置包含供应商名称、协议类型、API地址、凭据、实际模型名、逻辑别名、能力声明、超时和调用额度。能力声明必须经工具调用与结构化输出小样核实。
- 业务只使用统一协议，不直接配置各家密钥或SDK。兼容协议通过配置接入；新协议在网关增加适配，停车、交易及AI业务编排保持不变。
- 不预先指定网关产品。第1—2天按管理页面、协议适配、配置版本、在途任务固定版本、用量记录、部署复杂度及工时选型；复用现成方案时必须验证全部必需能力，不能因已有试部署就直接定案。
- Spring Cloud Gateway继续处理用户业务入口；模型网关不执行预约、支付、退款或结算工具。会话、知识检索、业务权限及事实核验留在AI编排和业务服务。

### 切换语义

本节“任务”指一次被受理的用户消息请求，包括该请求内的工具调用和后续模型生成，不指整个多轮会话。下一条新消息可采用新路由版本，会话槽位仍由业务服务保存。

- 首版仅一个活动配置，通过页面手动发布新路由版本；不自动跨供应商故障切换，不随机轮询。
- 新任务采用当前活动版本；已受理任务保存其路由版本，直到任务本轮所有模型调用结束都使用该版本，禁止中途更换供应商。
- 切换只影响新任务，无需修改业务代码、重新编译或重启业务进程；旧版本在在途任务完成前不得删除。
- 配置验证失败不替换原活动版本；回退发布上一有效配置。供应商故障或额度不足时降级到普通业务入口。
- 路由版本随请求在业务与网关之间传递；内部契约须同时返回实际供应商、模型及用量供追踪。网关产品不支持该语义时必须补足网关层适配或调整选型，不能把简单启停两条渠道等同于原子切换。
- 发布及回退使用独立模型管理权限，记录操作者、时间和配置版本；密钥服务端保存、页面脱敏，调用日志不包含密钥和无关个人信息。

### 接入边界

不承诺任意厂商的任意API都可仅填URL使用。协议兼容与模型能力分开验证；缺少工具调用或结构化输出能力的配置不能用于依赖该能力的正式场景。首次真实调用须确认供应商、模型和预算，费用按实际调用次数估算，包含多轮和工具结果后的再次生成。

## 4. 业务接口与安全约束

- 正式会话、知识及AI编排归identity-service。公共接口沿用POST /api/v1/ai/sessions、POST /api/v1/ai/sessions/{id}/messages、GET /api/v1/ai/sessions/{id}/messages；消息携带Idempotency-Key和expectedSessionVersion。
- 同会话最多一个活动请求；同键同参返回原结果或202，同键异参、忙会话及旧版本返回409。普通HTTP完整响应，服务端异步等待，不持有数据库事务或连接等待模型。
- 仅开放searchAvailableSpaces、retrieveParkingRules、getMyOrderBill三个只读工具，每轮最多2次工具调用。20秒总截止包含排队、网关、模型和工具；重试与切换不重置时限。
- 账单使用reservationId，返回billVersion、billAsOf、projectionUpdatedAt。模型仅选择reasonCode、factRefs、citations；金额和时间由后端注入，返回前复核版本，变化时新快照降级。
- 知识条目按规则与社区版本化，历史依据保留，缺失则说明无依据。追加数据库迁移，不修改已执行迁移。会话默认30天清理，不清除资金审计。
- 知识维护、AI日志及模型网关管理使用独立权限并审计；供应商凭据不进入浏览器业务代码、模型上下文或普通日志。

## 5. 验收与冻结

### 网关验收

1. 以相同业务代码、入口、项目凭据和模型别名，通过页面完成A→B→A切换；检查业务PID和启动时间未改变。
2. 切换期间在途任务继续使用原路由版本，新任务使用新版本；同一任务的工具后续生成不混用供应商。
3. 无效配置不能激活，故障时普通业务可用，回退后新任务恢复旧配置。
4. 验证管理权限、密钥脱敏、工具参数传输、结构化结果、用量与实际模型记录；协议可通不等于AI能力通过。
5. 两个真实供应商的验收须有可用账号及确认预算。仅有一个时先完成确定性双上游测试，真实切换明确标记未验收，不伪造通过。

### AI与工程验收

开发集与验收集分离，固定100条为查询30、规则30、账单20、边界20。M4执行一轮预评测：查询≥27/30，规则正确且引用有效≥27/30，账单AI正确完成≥18/20且展示事实全部正确，边界20/20；模板降级不计AI完成。AT07、AT08、迁移、构建、浏览器流程及核心业务冒烟通过，阻断和严重缺陷清零。

缺少M3真实业务支撑的必需场景保留阻塞状态，不移出验收集或更改分母。候选功能完成、M4通过和M5正式通过分别记录；存在必需验收阻塞时不得签收完整M4。

第13—14周用固定供应商、模型、路由版本、提示词、知识及数据执行三轮独立评测。AT06为10并发、每类每轮至少100个请求、三轮分别达标：正确完成率≥90%、降级率≤10%、正确完成请求完整响应P95≤15秒；另完成混合负载和EX01—EX03。

第12周冻结功能范围及候选版本，之后可修复代码、提示词和知识，但须更新版本并重新验证。评测中途切换模型或修改配置后必须重新完成对应完整评测，不拼接不同版本的通过结果。
