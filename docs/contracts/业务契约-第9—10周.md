# 第9—10周增量业务契约

更新日期：2026-10-31。范围为已实现的退款、权限与恢复；正式结算、对账不由本文宣称交付。

## 退款申请与审批

POST /api/v1/refund-applications：DRIVER 本人已完成订单，要求 Idempotency-Key；请求包含 reservationId、amountFen（正整数分）、reason（1—500字）、evidence（最多2000字），重提时包含 previousApplicationId。截止时间为原始完成时间加7天，达到截止时拒绝新事实申请；完成时间缺失则阻断，不能以迁移时间替代。相同事实或原幂等请求返回已有结果。驳回后必须关联本订单本人被驳回申请，提供非空且不同的新证据。

GET /api/v1/refund-applications?page=1&size=20：司机仅查本人；平台要求 REFUND_READ。状态为 PENDING、APPROVED、REJECTED、COMPLETED、PARTIAL_FAILED。

POST /api/v1/refund-applications/{id}/decision：要求 REFUND_APPROVE，必须提供 Idempotency-Key；同键同参返回原审批结果，同键异参409。正文 decision 为 APPROVE 或 REJECT，note 为1—500字。仅 PENDING 可审批，不同键重复审批返回409并要求刷新。批准在订单锁内映射历史退款并按成功收款ID分配，创建退款尝试和收款桥接记录；批准不等于渠道成功。

额度同时受订单实收、单笔收款实收、父申请批准金额限制。活动尝试（含未知、人工核查）继续占用额度，成功结转，确定失败释放；失败重试重新分配并检查三层额度。父状态根据有效叶节点执行结果汇总。前端支持申请、驳回、新证据重提、审批和执行结果查询。

## 历史退款与统一自动退款

V008 的 refund_receipt_allocation 支持一个历史退款分配到多笔成功收款。POST /api/v1/admin/refund-attempts/map-history?after=0 要求 FUNDS_RECOVER，每批最多100个订单，返回 items（PASS 或 REVIEW）、next、hasMore。逐订单事务处理；收退款事实或额度不一致时该订单回滚并报告 REVIEW。映射保留原渠道号、状态、金额、流水，不重新调用渠道。反复执行不重复建父申请或分配。

关闭订单的自动退款与人工退款共用 RefundLedger、父申请和收款分配。自动目标按预付实收及已有父目标补足差额；已失败但仍有退款义务的父目标保留，交由失败重试处理，避免另起自动退款造成重复义务。退款执行、成功入账和后续自动补差受订单锁、租约版本与唯一流水约束。

## 失败重试与调度

POST /api/v1/admin/refund-attempts/{id}/retry：要求 FUNDS_RECOVER、Idempotency-Key 和 reason（1—500字）。仅 REFUND 且确定 FAILED 可创建后继；UNKNOWN、REVIEW、SUCCESS 不允许。返回202表示受理。重试适用于已关联父申请的退款，也兼容历史自动退款映射；前端不能指定金额、用户或渠道号。同键异参409；同键同参返回原结果；不同键重复请求同一失败项返回同一直接后继，不创建分叉。

GET /api/v1/admin/refund-attempts?page=1&size=20 要求 REFUND_READ，返回分页白名单字段。前端按账号保存结果未知请求的原键和原因，刷新后复用；只读账号不能重试。

query_count 与累计 retry_count 分离。首次派发不消耗查询预算，默认最多5次原号查询；查询前持久登记次数，预算耗尽转 REVIEW，仍占额度。恢复查询不补发扣款；人工恢复重置查询预算而保留累计次数和原号。租约和到期使用UTC系统时钟，不随演示时钟跳变。

配置：PAYMENT_QUERY_BUDGET（默认5）、PAYMENT_LEASE_SECONDS（30）、PAYMENT_BACKOFF_SECONDS（5）、PAYMENT_MAX_BACKOFF_SECONDS（60）、PAYMENT_POLL_MILLIS（1000）。

## 账号权限与故障统计

GET /api/v1/admin/users/{id}/permissions 要求 USER_MANAGE；PUT 还要求数据库中的独立 ACCOUNT_AUTHORIZE 能力，禁止修改本人的资金权限。角色变更也要求该能力，不能通过角色提升绕过授权。PUT 使用 version 和 permissions；可覆盖平台账号的 REFUND_READ、REFUND_APPROVE、FUNDS_RECOVER、SETTLEMENT_EXECUTE，版本冲突拒绝，变更写审计并撤销会话。未配置账号保留角色默认权限；跨服务使用身份服务提供的有效权限，缺失则失败关闭。ACCOUNT_AUTHORIZE 不允许通过资金表单授予；V006为最早的启用平台账号初始化该能力，空库演示初始化时授予演示管理员。系统必须保留至少一名启用的授权管理员。一般平台账号不再具备角色和资金授权能力。此策略分离授权能力，但不强制授权管理员与资金操作员身份互斥。新增结算权限不代表结算功能已实现。

SimulatedChannel 支持 SUCCESS、FAILED、UNKNOWN、0—60000ms延迟和提交后响应丢失；通过配置及测试夹具注入，未提供线上热更新管理API。非演示配置拒绝启用故障。channel_operation 独立提交；channel_call 独立持久记录每次 SUBMIT/QUERY 的开始、返回/错误、结果及完成时间。未结束 STARTED 表示调用中或中断，不能推断资金失败。内存计数用于测试，跨重启统计以数据库为准。此通道为持久模拟适配器，不是第三方支付机构联调。

2026-11-02：退款申请、审批和分页 HTTP 接口使用 RefundContracts 强类型请求/响应；父状态汇总统一由 RefundLedger.refresh 执行。浏览器持久保存未确认审批的原键、申请和审批说明，支持原请求核对。

2026-11-03 补充：退款执行列表、失败重试和历史映射 HTTP 输出也使用强类型 DTO；内部持久层仍保留 Map 兼容接口。金额与编号通过精确整数转换拒绝小数及越界，避免反序列化静默截断。启动脚本须等待网关可路由到交易服务后才报告就绪。
