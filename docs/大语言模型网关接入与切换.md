# 大语言模型网关接入与切换

## 当前演示环境的供应商切换

在平台管理的“模型供应商管理”页面保存一个新版本，填写兼容聊天协议的 HTTPS 基础地址、模型名、凭据文件名、输入和输出等值价格、价格版本，以及单次最大输出 Token。服务端从 `deploy/secrets` 读取对应的 properties 文件，键名为 `api-key`。模型调用及预算预留使用同一版本的输出上限；旧配置默认 1536。

免费配置须确认免费调用资格。首次为新主机配置付费调用时，填写累计授权额度并勾选授权。同一供应商主机的后续模型和凭据版本共享原有额度；阶段预算同时生效。DeepSeek 独立上限为 5 元，计入阶段 50 元。首次接入前应核实供应商支持的模型参数，必要时勾选关闭思考模式。

点击“检查配置”，服务会使用该版本凭据验证工具调用和结构化应答。通过后在 10 分钟内点击“设为活动配置”。“恢复上一配置”会发布一个新路由版本，上一配置也需要有效检查。已经开始的模型调用沿用它捕获的版本。

明确的通用规则可直接检索本地已发布条款。涉及具体社区时匹配社区名称或编号，存在多个可能的社区时先追问。带有明确订单上下文的本人账单继续校验归属，并在解释前后重新核对版本。

## 架构与本次范围

```text
悦享泊后端 → LlmGateway → New API /v1/chat/completions → 已配置供应商
                           model=parking-assistant
```

New API独立运行，管理入口 http://127.0.0.1:3300。既有Spring Cloud Gateway继续负责业务路由；模型网关负责供应商协议、密钥和模型映射，不执行停车业务工具。正式AI仍按第11—12周计划在identity-service编排；当前parking-service的prototype仅用于接入验证，保持realModelAccepted=false，不能据此宣称找车位、规则检索或账单解释已验收。

本机单节点开发环境使用独立SQLite持久卷，不触碰现有业务MySQL。生产部署须迁移到受支持的独立数据库并验证备份恢复。镜像固定为初始化时的RepoDigest，见deploy/llm-image.lock.json。停止网关不能使用down -v删除数据卷。

## 启动与首次配置

在项目根目录的PowerShell 7执行：

```powershell
./scripts/Initialize-LlmGateway.ps1
./scripts/Start-LlmGateway.ps1
```

初始化只在不存在本地网关配置时生成密钥并锁定镜像，重复执行不覆盖。打开管理入口，按页面完成管理员初始化。管理员密码和供应商密钥不要粘贴到聊天或提交到Git。

在“渠道”中添加供应商：选择受支持的协议类型，填写上游Base URL、API Key和模型。对外模型列表包含parking-assistant，模型映射例如：

```json
{"parking-assistant":"供应商实际模型名称"}
```

模型映射方向为“业务请求别名→供应商模型名”。分组必须与项目调用令牌一致。在网关中配置该别名对应的计费设置和有限额度，避免未配置价格导致调用被拒绝。费率依据供应商实际定价登记，网关额度估算不代替供应商账单。关闭自动渠道测试、自动重试及跨供应商故障切换；测试和评测前须确认模型与调用预算。

创建仅允许该分组和parking-assistant的项目调用令牌；业务使用此令牌，不使用供应商密钥或管理员令牌。编辑被Git忽略的deploy/secrets/llm-gateway.properties：

```properties
enabled=true
base-url=http://127.0.0.1:3300/v1
model=parking-assistant
api-key=网关签发的项目令牌
```

该文件仅服务端读取，每次请求读取一致的配置快照；建议以临时文件写完后原子替换。初始模板enabled=false，不发起付费请求。首次安装新的Java适配器需正常构建并重启业务一次；之后供应商切换不需要重新构建或重启。当前运行中的旧JAR不会因源码修改自动升级。

## 通过管理页面切换

1. 添加目标渠道，配置相同别名parking-assistant及目标实际模型；先保持生产路由不变。
2. 使用独立验证分组和令牌测试目标渠道的文本、工具调用及结构化输出；调用须在已确认预算内。兼容接口不等于模型能力相同。
3. 本项目默认仅保留一个可用于生产别名的启用渠道；暂停新的助手请求并等待当前请求结束，再禁用旧渠道、启用新渠道。操作期间请求可能短暂降级，不承诺零中断原子切换。
4. 用相同业务入口与别名验证新请求到达新渠道；业务服务PID及启动时间应保持不变，网关日志确认实际渠道、模型和用量。
5. 验证失败则禁用新渠道、恢复旧渠道。不得同时启用同优先级同别名渠道形成非预期随机路由。

管理页面修改数据库渠道配置；本地关闭渠道内存缓存。切换不改变已发往旧供应商的在途请求。正式多次模型调用任务上线后，必须在会话空闲时切换，评测期间不改变映射；日志记录配置版本和实际渠道，不能只保存别名。

## 适配器行为与验证边界

LlmGateway固定发送OpenAI兼容的非流式请求，支持messages和tools传输；不直接执行模型提出的工具。工具参数、授权、事实核验仍由业务编排负责。每次调用接收剩余总时限，最大20秒，不自动重试或跟随重定向；网关中继超时18秒。网关故障分别映射为AI_BUSY、AI_TIMEOUT、AI_UNAVAILABLE，不透传上游错误正文。

prototype默认保留模型桩。启用网关后normal请求走真实网关，故障桩仍仅在管理员演示权限下使用。prototype当前只验证文本接入，不把订单、联系方式或业务数据库记录发送到模型。后续正式业务调用必须使用授权后的最小事实投影。

验证分三层：

- 自动化本地HTTP桩：固定地址/别名下更换上游返回、工具往返、错误脱敏、超时、429、重定向拒绝、配置停用等；不计真实供应商验收。
- 部署：Compose校验、镜像摘要、网关健康接口和管理首页。
- 待配置后验收：真实供应商A→B→A、业务进程不重启、渠道日志核对、三类AI能力回归；供应商与预算确认前不执行。

原scripts/business-smoke.mjs的AI分组明确断言STUB；运行此组前保持enabled=false，不能将它作为真实网关验收，也避免普通业务回归意外产生模型费用。

## 对第11—12周计划的补充

- 第1—2天：固定网关部署与项目令牌，供应商选型变为“网关渠道配置及能力准入”；业务只保留一个网关适配器。
- 第3天：验证网关不可用、超时和限流时核心业务隔离。
- 第12周验收：新增同一业务进程、同一别名下A→B→A切换及回退检查；真实双供应商验证依赖两个可用渠道及预算。
- 新增网关部署、渠道配置、能力兼容和切换测试计入第2天工时复估，不自动承诺原44小时足够。
